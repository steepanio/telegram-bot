# Telegram Bot — Module 1
## Bot Skeleton + Command Dispatcher (с юнит-тестами)

Этот репозиторий — учебный проект, цель которого — научиться разрабатывать
**тестируемые, поддерживаемые и архитектурно корректные Telegram-боты на Java**.

Проект разбит на **чекпоинты**.  
❗ **Каждый чекпоинт = отдельный Pull Request.**

---

## 🔁 Обязательное правило Pull Requests

- Каждый чекпоинт выполняется **в отдельной ветке**
- На каждый чекпоинт создаётся **отдельный Pull Request**
- PR считается завершённым **только после код-ревью**
- Все правки по ревью вносятся **в тот же PR**

❌ Запрещено:
- объединять несколько чекпоинтов в одном PR
- пушить напрямую в `main`
- писать код без тестов
- оставлять TODO / FIXME

---

## 🎯 Цель модуля

После завершения модуля ты должен уметь:

- писать Telegram-бота, где бизнес-логика не зависит от Telegram SDK
- использовать паттерн Command
- проектировать код, который легко тестировать
- писать юнит-тесты параллельно с кодом
- работать через Pull Requests как в реальной команде

---

## 🧱 Архитектурные принципы (ОБЯЗАТЕЛЬНО)

- Telegram SDK разрешён **только** в адаптере
- Core-логика не знает, что такое Telegram
- Команды не работают напрямую с инфраструктурой
- Всё, что можно протестировать — тестируется

# 🚀 Чекпоинты

---

## ✅ Чекпоинт 1 — Старт проекта и тестовая среда

### Цель
Подготовить **рабочее окружение**, в котором можно:
- запускать приложение
- писать и запускать тесты
- не бояться рефакторинга

### Что нужно сделать

1. Создать Gradle-проект:
    - использовать `application` plugin
    - корректно настроить `mainClass`
2. Подключить зависимости:
    - JUnit 5 (обязательно)
    - Mockito (по желанию)
3. Настроить запуск тестов:
    - `useJUnitPlatform()`
4. Подключить JaCoCo:
    - отчёт о покрытии
    - минимальный порог (40–50% достаточно)
5. Реализовать `main()`:
    - приложение должно стартовать
    - реального подключения к Telegram пока не требуется
6. Конфигурация:
    - token и botName **не хардкодить**
    - использовать env или config-файл

### Тесты
- минимум 1 простой тест:
    - успешно запускается
    - доказывает, что тестовая среда настроена

### Что проверяется на ревью
- проект собирается
- тесты запускаются
- нет секретов в коде
- структура аккуратная

📌 **Оформить как отдельный PR**

## ✅ Чекпоинт 2 — Парсинг входящих сообщений (DTO)

### Цель
Научиться **отделять входящие данные от бизнес-логики** и писать чистые, тестируемые парсеры.

### Что нужно сделать

1. Создать `IncomingMessageDTO`, содержащий:
    - `userId`
    - `chatId`
    - `text`
    - `command`
    - `args`
    - `isCallback`
    - `callbackData`
2. Реализовать парсер:
    - вход → DTO
    - логика не зависит от Telegram SDK
3. Поддержать сценарии:
    - `/start`
    - `/salary 100000`
    - несколько аргументов
    - лишние пробелы
    - обычный текст без команды

### Тесты
- команда без аргументов
- команда с аргументами
- пробелы в начале/конце
- текст без `/`
- null / пустой текст (явно выбранная стратегия)

### Что проверяется на ревью
- парсер — чистая логика
- edge-cases обработаны
- тесты читаемые и стабильные

📌 **Оформить как отдельный PR**

## ✅ Чекпоинт 3 — Команды и диспетчер

### Цель
Реализовать **паттерн Command** и централизованную маршрутизацию.

### Что нужно сделать

1. Интерфейс `BotCommand`:
    - `supports(IncomingMessageDTO)`
    - `handle(IncomingMessageDTO)`
2. `CommandDispatcher`:
    - принимает список команд
    - выбирает первую подходящую
    - fallback на `UnknownCommand`
3. `BotResponse`:
    - `chatId`
    - `text`
    - опционально `keyboard`

### Тесты
- корректный выбор команды
- fallback
- конфликт команд
- выбранная стратегия обработки ошибок

### Что проверяется на ревью
- отсутствие if/else-адской логики
- расширяемость
- детерминированность

📌 **Оформить как отдельный PR**

### Цель

### Что нужно сделать

    - Update → DTO
    - DTO → dispatcher

2. Создать интерфейс `MessageSender`

### Тесты
- dispatcher вызывается
- MessageSender вызывается с ожидаемыми данными
- Telegram SDK не используется в тестах

### Что проверяется на ревью

- отсутствие Telegram типов в core-логике
